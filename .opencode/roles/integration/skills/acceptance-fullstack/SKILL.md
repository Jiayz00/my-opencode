# 全栈验收

## 概述

本技能处理核心工作流第 5 步中的全栈验收路径。测试在测试容器中进行（而非本地），覆盖完整的前端-后端-数据链路。

## 服务器访问

本技能需要访问测试服务器。遵循 `vibe-core` 中的**敏感信息处理**规则：

1. 检查环境变量：`OPENCODE_TEST_HOST`、`OPENCODE_TEST_USER`、`OPENCODE_TEST_KEY`、`OPENCODE_TEST_PORT`、`OPENCODE_TEST_DIR`
2. 如果缺失，使用 `question` 一次向用户询问一个变量
3. 绝不将凭据保存到文件或回显

## 流程

### 1. 预检查
- 所有单元/集成测试通过
- 构建成功（前端 + 后端）
- 测试服务器可访问（SSH 连接已验证）

### 2. 部署到测试容器
- SSH 进入测试服务器：`ssh -i %OPENCODE_TEST_KEY% %OPENCODE_TEST_USER%@%OPENCODE_TEST_HOST% -p %OPENCODE_TEST_PORT%`（端口变量按 vibe-core 完整模板）
- 进入部署目录：`cd %OPENCODE_TEST_DIR%`
- 部署：`docker-compose up -d --build`（或等效命令）
- 验证容器成功启动：`docker ps`
- 确认所有服务都在运行：检查容器日志
- **部署失败**：检查容器日志 → 重试一次 → 仍失败则停止并报告，不进入验证阶段

### 3. 端到端验证
走完完整的用户流程：
- 前端连接后端
- API 端点正确响应
- 数据端到端流转（UI → API → DB 并返回）
- 错误传播正常（后端错误 → 前端展示）

如果发现问题：
- 小问题（字段名笔误等）：直接修复并重新验证
- 方案问题：汇总完整信息并附日志/证据，返回核心工作流第 2 步
- 不得进入用户报告阶段

### 4. 用户报告
使用 `question` 工具呈现：
- 实现摘要
- 测试环境 URL
- 需要验证的具体流程/功能
- 测试所需的账户/凭据

### 5. 用户验收
- 等待用户确认验收
- 如果用户反馈问题或要求更改 → 判断级别：小修返回第 4 步；方案问题返回第 2 步；需求变更返回第 1 步（与 vibe-core 回环规则一致）
- 如果用户接受 → 进入第 6 步

## 验证

- [ ] 应用已部署到测试容器
- [ ] 前端 Mock 已关闭，真实接口连通
- [ ] 前端-后端连通性已验证
- [ ] 端到端流程正常（UI → API → DB）
- [ ] 错误处理端到端正常
- [ ] 已通过 `question` 通知用户
- [ ] 用户已接受

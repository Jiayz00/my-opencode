# 安全审计

## 概述

只读安全审查。你分析代码中的漏洞并给出发现。**不得修改任何代码。**

**多角色评审中的角色：** 在 Step 2 规格评审 / Step 4 代码评审中，本 skill 由安全工程师子代理加载，评审规格/计划或代码改动的安全性，回答"本次修改会不会引入安全风险"。代码评审模式下发现必须带 file:line 引用。

## 工作流调整

### 第 1 步 — 澄清
询问用户：
- 范围：审计什么（特定文件、模块，还是整个代码库）
- 威胁模型：风险画像是什么？（面向公众？处理敏感数据？PCI/HIPAA 等合规要求？）
- 是否有需要跟进的历史审计发现

### 第 2 步 — 分析（替代规格与计划）
从以下安全维度进行审查：
- **认证：** 会话管理、密码处理、MFA、令牌验证
- **授权：** 访问控制检查、权限提升路径
- **输入验证：** SQL 注入、XSS、命令注入、SSRF
- **数据保护：** 加密（静态和传输中）、密钥管理
- **依赖：** 已知漏洞版本、供应链风险
- **配置：** 默认凭据、调试端点、CORS、安全响应头

### 后端安全专项（必查，后端改动时逐项过）

**API 安全（OWASP API Security Top 10 2023 视角）**
- 对象级授权（API1 BOLA）：直接通过 ID 访问资源时是否校验归属（`/users/{id}` 越权读他人数据）？
- 对象属性级授权（API3 BOPLA）：响应/请求是否泄露或允许修改不应暴露的字段（如 `isAdmin`、内部状态）？
- 功能级授权（API5 BFLA）：管理端点/高权限操作是否只校验"已登录"而未校验角色？
- 资源消耗（API4）：无分页列表、无限请求体、无超时、无限流（登录/公开端点）？
- SSRF（API7）：服务端请求外部 URL 时是否校验目标（内网地址、file:// 等）？
- 敏感业务流程（API6）：可自动化滥用的流程（注册、下单、验证码）是否有防滥用（限流/验证码）？
- 不安全消费（API10）：调用第三方 API 是否校验响应结构、处理异常？

**认证与凭据**
- JWT：`exp` 过期必需、算法固定（禁 `none`/弱算法）、签名密钥强度；令牌如何撤销？
- 密码存储：加盐强哈希存储（bcrypt/argon2），不存明文（OWASP 密码存储指南）
- 会话：cookie 标志（HttpOnly/Secure/SameSite）、会话过期与空闲超时
- 密钥管理：密钥不在代码/仓库（见 git-workflow 脱敏表）、轮换机制

**输入与输出**
- 输入校验：所有外部输入（body/query/headers/file）白名单校验；SQL 注入（参数化查询/ORM 转义）、NoSQL 注入、命令注入、路径遍历
- 输出：错误响应不泄露堆栈/SQL/内部路径；日志不记录密码/token/敏感字段（OWASP A09）

**依赖与配置**
- 依赖漏洞扫描（npm audit / pip-audit / 漏洞扫描）结果，高危漏洞处理状态
- 安全配置：默认凭据、调试端点/文档在生产暴露、CORS 白名单、安全响应头（HSTS/CSP 等）
- 数据保护：静态数据加密（敏感字段/数据库）、传输加密（TLS）、备份可恢复

编写发现报告：
- 严重级别：严重 / 高 / 中 / 低 / 提示
- 位置：代码评审模式下必须为 file:line（规格评审用文档路径/章节）
- 影响：攻击者可以利用它做什么
- 修复：具体的修复步骤

### 第 3 步 — 门禁
提出："审计完成。发现 [X 个严重、Y 个高、Z 个中] 问题。我可以展示报告吗？"

### 第 4 步 — 不适用（只读）

### 第 5 步 — 展示发现，等待用户反馈。

### 第 6 步 — 不适用（只读，无兼容性回归）

## 规则

- 只读审查，不修改任何文件
- 不运行会修改系统的命令
- 报告内建议须自洽（与其他角色的冲突由主代理交叉复核裁决）

## 验证清单

- [ ] 所有安全维度都已覆盖
- [ ] 后端改动已逐项过"后端安全专项"清单（OWASP API Top 10 视角）
- [ ] 每个发现都包含严重级别、位置、影响和修复
- [ ] 代码评审模式下每个发现均带 file:line 引用
- [ ] 报告内建议已自洽检查
- [ ] 审计期间未修改任何代码
- [ ] 报告可执行（用户能根据发现采取行动）

# 前端依赖升级

## 概述

前端依赖（npm 生态）升级频繁。本技能规范升级流程：**先审查变更，再逐个升级，最后验证**。禁止盲目 `npm install xxx@latest` 后"看运气"。

适用于：单个依赖升级、批量依赖升级、npm audit 高危漏洞修复。**边界：升级影响后端接口/契约或需全栈验证时，停止并转结合人员按全栈依赖升级流程处理（`dependency-update` 结合版）。**

## 步骤调整

### 第 1 步 — 需求澄清
询问：
- 升级什么？（具体包名，或"全部依赖"）
- 目标版本？（指定版本 / latest / 修复漏洞）
- 升级动机？（新功能、漏洞修复、性能、维护要求）
- 有无时间或范围约束？（不影响某功能、某浏览器）

### 第 2 步 — 规格与计划
- **审查 changelog / release notes**（GitHub Releases、CHANGELOG.md、npm 页面）：
  - 破坏性变更（breaking changes）清单
  - 弃用 API（deprecations）——作为后续迁移清单
  - 与新版本相关的已知问题（GitHub issues）
- **影响面分析**：grep 代码库中该包的所有使用点（import、API 调用、配置项），评估哪些代码可能受影响
- **升级策略**：
  - 相邻 major 逐个升（如 v2→v3→v4），跳过 major 升级风险高
  - 一次只升一个 major 范围，验证后再继续
  - 批量 minor/patch 可合并（低风险），但须记录全部变更
- **验证计划**：升级后跑什么（测试套件、构建、类型检查、lint）
- **回滚方案**：记录当前锁定版本，升级失败可 `git revert` 或 `npm install <旧版本>`

### 第 3 步 — 权限门禁
呈现："升级 [包名] 从 [版本] 到 [版本]。破坏性变更：[摘要]。影响面：[N 个文件]。我可以继续吗？"

### 第 4 步 — 执行升级
- 用精确版本升级：`npm install <pkg>@<version>`（**不用 `@latest`**，锁定已验证的版本）
- 升级后立即检查：
  - `npm audit` 结果（升级不应引入新的高危漏洞）
  - peerDependencies 冲突（`npm ls` 检查依赖树完整性）
  - lockfile 已更新并提交（`package-lock.json`/`pnpm-lock.yaml` 必须入库）
- 逐 major 升级时，每步之间运行测试
- **编码修复**：升级导致的 breaking changes 在本技能内处理（改 API 调用、配置、类型），但要遵守最小改动原则——升级任务里不夹带功能开发

### 第 5 步 — 验收
- 完整测试套件通过
- 构建 + 类型检查 + lint 通过
- 手动冒烟：受影响功能正常（可加载 `acceptance-frontend` 自动化验证）
- 记录：升级后的实际版本、处理过的破坏性变更

### 第 6 步 — 兼容性
- 门禁：`question` 请求许可
- 回归重点：所有依赖被升级包的功能（按第 2 步影响面清单逐项过）
- 跨浏览器验证（升级包可能改变渲染行为）
- 性能冒烟：升级包是否引入明显体积/加载变化（对比 bundle 分析，见 optimization-frontend）

## 特殊场景

- **npm audit 高危漏洞**：优先修复。无直接升级路径时记录缓解措施（配置规避、等待上游修复），不擅自换库
- **过旧 major（落后 2+ 个版本）**：先逐 major 升到中间版本再继续，禁止直接跳升
- **peerDependencies 冲突**：优先调整依赖版本匹配，不轻易 `--force`/`--legacy-peer-deps`（会掩盖真实问题）
- **升级导致测试失败**：判断是测试过时还是行为变更；行为变更需确认是否符合预期，禁止静默改测试掩过

## 常见借口

| 借口 | 现实 |
|------|------|
| "升到 latest 就行" | latest 可能有你还没准备好的 breaking changes。锁定验证过的版本 |
| "小版本升级不用看 changelog" | minor 也可能有行为变更（弃用、默认值变化）。至少扫一眼 release notes |
| "升级失败就回滚，不用提前计划" | 回滚前记录当前版本是计划的一部分，失败时才知道回到哪 |
| "顺手把相关代码也重构了" | 升级任务只做兼容性修复。重构另开任务 |

## 验证清单

- [ ] changelog 已审查，breaking changes 已列出
- [ ] 影响面（所有使用点）已盘点
- [ ] 升级用精确版本，lockfile 已更新并提交
- [ ] 逐 major 升级且每步验证
- [ ] `npm audit` 无新增高危漏洞
- [ ] 测试/构建/类型/lint 全部通过
- [ ] 受影响功能回归通过（第 6 步）
- [ ] 回滚方案已记录

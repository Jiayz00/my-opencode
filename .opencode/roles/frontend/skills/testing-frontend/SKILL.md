# 前端测试策略

## 概述

本技能定义前端测试的分层策略与方法。用于第 4 步开发时配套写测试、第 5 步验收时执行测试、review-qa 评审时作为测试方案依据。

**核心原则**：测试"真正会坏的东西"。覆盖按风险分配——核心用户路径重覆盖，边缘路径适度覆盖，不追求无意义的高覆盖率。

## 测试思想（Testing Library 原则）

- **测行为，不测实现**：像用户一样使用软件——按可见文本/角色/标签查询（`getByRole`/`getByLabel`/`getByText`），不按组件内部状态或类名断言。用户不关心 `isLoading` 是 true 还是 false，他们看到的是"加载中"文案
- **越像用户，测试越有价值**：查询优先顺序——用户可见的角色/文本 > 语义标签 > 测试 id > 类名/内部结构（后者仅作为最后手段）
- **Testing Trophy 修正金字塔**：传统金字塔重单元、轻 E2E；Trophy 主张**集成测试是主角**——组件与状态、路由、API 层协作处的测试数量最多、最有价值，因为它们覆盖真实交互路径；单元测试少而精，E2E 只覆盖关键旅程
- 静态分析（TS/ESLint）是最廉价的一层"测试"，先于所有运行时测试
- 写不出"像用户"的测试，往往是因为组件不可访问（没有 label/角色）——这是改进产品的信号，不是改测试手段的信号

## 测试金字塔（Trophy 修正）

```
      E2E（最少）         Playwright/Cypress：关键用户旅程
   单元测试（少而精）      纯函数、独立组件、Hooks
 集成测试（主角，最多）    组件树 + 状态管理 + API 层协作
```

| 层 | 测什么 | 工具 |
|----|--------|------|
| 集成（主角） | 组件组合、路由、状态管理、API 层（Mock 服务） | Testing Library + MSW |
| 单元 | 纯函数、格式化、状态计算、独立组件渲染 | Vitest/Jest + Testing Library |
| E2E | 关键用户旅程（登录、下单、注册）跨页面流转 | Playwright / Cypress |

## Mock 策略

- **不过度 mock**：只 mock 不稳定/外部边界（网络、时间、浏览器 API），不 mock 内部实现细节
- 服务层（API）统一用 **Mock Service Worker (MSW)**：在网络层拦截，组件层零改动
- **Mock 数据与契约字段一致**：字段名、类型、嵌套结构完全对齐 `docs/api-contracts/`；含成功/错误/空/加载态四类 fixture
- Mock 是开发期替身，真实接口替换由结合人员执行——mock 层代码要可一键切换（环境变量/开关）
- 绝不 mock 你要断言的逻辑本身（如 mock 掉组件内部状态变化去测点击，测了个寂寞）

## 契约测试

- API 层消费者驱动：前端维护请求/响应类型定义（TS interface），与契约文档双向校验
- 轻量做法：API 层对响应做运行时校验（zod 等），契约变更 → 前端类型报错，第一时间发现
- 完整做法：Pact 等消费者驱动契约测试，CI 中验证前端期望与后端实现一致
- 契约不一致时**禁止前端自行假设字段**：记录差异，交结合人员协调

## 视觉回归

- 关键页面/组件截图基线对比（Playwright `toHaveScreenshot` 或 Chromatic）
- 基线更新需要人工确认（防止把真实回退当预期）
- 覆盖：组件所有状态（数据/加载/空/错误）、响应式断点

## a11y 测试

- 组件测试内嵌 jest-axe 断言：`expect(screen.getByRole('button')).toBeAccessible()` 或等价断言
- E2E 中跑 axe 扫描关键页面
- Lighthouse a11y 评分纳入验收（≥ 90）

## 覆盖率与 CI 门禁

- 覆盖率阈值按核心模块设定（建议核心 ≥ 80%，非核心不设硬门槛但需有测试）
- **性能预算 CI**：bundle 体积、Lighthouse 分数、核心 Web Vitals 超阈值即构建失败（性能预算细节见 optimization-frontend）
- 测试必须**原子、独立、可重复**：不依赖执行顺序、共享可变状态、真实网络
- 失败的测试是阻塞项，禁止"跳过测试提交"；`skip`/`todo` 必须有理由

## 测试数据

- fixture 数据真实可信，模拟真实场景（边界值、超长文本、特殊字符）
- 敏感数据匿名化：不使用真实用户隐私数据做 fixture
- 时间相关测试注入时钟（vi.useFakeTimers），不依赖真实等待

## 本角色边界

- 前端测试在本角色内完成：单元/组件/集成/E2E 前端旅程
- 前后端联调级测试、契约对齐验证由结合人员（feature-dev-integration）执行，本角色不重复
- 与 review-qa 关系：review-qa 审查测试方案的覆盖与回归风险，本技能提供测试方法本身

## 验证清单

- [ ] 核心用户路径有 E2E 覆盖（至少 1 条关键旅程）
- [ ] 关键组件有组件级测试（渲染 + 交互 + 状态）
- [ ] 业务纯函数有单元测试
- [ ] 测试用角色/文本/标签查询（无实现细节断言）
- [ ] Mock 与契约字段一致，四类 fixture（成功/错误/空/加载）齐备
- [ ] 视觉回归覆盖关键页面与状态
- [ ] a11y 断言嵌入组件测试或 E2E 扫描
- [ ] 覆盖率阈值达标、无跳过测试
- [ ] 测试原子、独立、可重复

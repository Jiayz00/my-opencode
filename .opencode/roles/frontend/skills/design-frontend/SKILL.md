# UI 设计质量

## 概述

本技能保障 UI 的视觉质量与独特性。AI 生成的设计容易落入模板化套路（米白底+衬线大标题+陶土色点缀；近黑底+荧光绿点缀；报纸排版细线+零圆角）。本技能要求：**设计要服务于具体需求，而不是默认模板**。适用于：

- **第 1-2 步（澄清与规格）**：确定设计方向与 tokens
- **第 4 步（开发）**：按设计计划实现，不自作主张
- **review-frontend-arch**：作为设计质量维度审查依据

**核心原则**：设计是功能的一部分。用户界面首先要理解起来容易、用起来顺畅；美观服务于理解。

## 两遍法（Process）

### 第一遍：设计计划（动手前）

产出紧凑的设计 token 系统，四要素：

1. **色板**：4-6 个具名 hex 值（主色/辅助色/文字/背景/语义色），每个颜色有用途说明
2. **字体角色**：至少 2 个角色——展示字体（有性格、克制使用）+ 正文字体（可读性优先）；如需数据/说明文字加工具字体
3. **布局概念**：一句话描述 + ASCII 线框对比 2-3 个布局方案
4. **签名元素**：这个页面唯一被记住的视觉元素（体现需求本质的那个点）

### 第二遍：复核（构建前）

对照需求检查设计计划：
- 每个选择是否是为这个需求做的，还是换任何项目都会这么选？
- 是 → 修改该部分，说明改了什么、为什么
- 复核通过后才开始写代码，颜色/字体/间距全部从 token 系统推导，不临时造值

### 构建 + 自批评

- 按计划实现；CSS 选择器注意 specificity 冲突（避免 `.section` 与元素选择器互相覆盖 margin/padding）
- 构建中持续自批评：签名元素之外保持克制，删除不服务需求的装饰
- 空间允许时截图检查自己的作品（一张图胜过千行代码）

## 设计 tokens 与主题

- 颜色、间距、圆角、阴影、字体走 design tokens，**禁止硬编码值**（与 review-frontend-arch 一致）
- 间距用 8pt 网格体系（4/8/16/24/32/48）
- 深色模式：两套主题都从 tokens 推导，不单独造色
- 响应式：移动端优先布局，断点处不破坏排版意图

## 排版

- 字号比例清晰（如 12/14/16/20/24/32），行高与字号配套
- 展示字体克制使用（标题/数字），正文保持可读性
- 文本对比度达标（见 accessibility-frontend）

## 界面文案（写作即设计）

- **从用户侧写**：命名用用户认识和控制的东西（"通知管理"而非"Webhook 配置"）
- **动词开头**："保存更改"而非"提交"；同一动作全程同名（按钮写"发布"，提示也写"发布"）
- **失败与空状态是指引而非态度**：说明发生了什么、如何解决；错误不道歉、不模糊
- **空屏幕是行动邀请**：给出下一步动作，而非孤零零的"暂无数据"
- 具体优于聪明；一句人话优于炫技措辞

## 可访问性底线（不可妥协）

- 响应式到移动端且可用
- 键盘焦点可见
- 尊重 `prefers-reduced-motion`
- 对比度达标（WCAG AA）

## 常见借口

| 借口 | 现实 |
|------|------|
| "这是流行风格，用的人多" | 流行 ≠ 适合。为需求做选择，不为模板做选择 |
| "先写代码，样式后补" | 设计决策（tokens/布局）影响组件结构。先定方向再写代码 |
| "这个配色我临时觉得好看" | 颜色来自 token 系统，不进临时值。改 token，不改特例 |
| "文案差不多就行" | 文案是界面的一部分。错误的文案让用户困惑 |

## 验证清单

- [ ] 设计计划（色板/字体/布局/签名）已产出并对照需求复核
- [ ] 颜色/字体/间距全部来自 tokens，无硬编码
- [ ] 有明确的签名元素，其余部分克制
- [ ] 文案从用户视角写，动作动词开头、名称全程一致
- [ ] 空状态/错误状态有引导，不空摆
- [ ] 响应式、键盘焦点、reduced motion 达标
- [ ] 对比度满足 WCAG AA

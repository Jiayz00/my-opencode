# 架构设计

## 概述

做技术决策和系统设计。流程只到 Step 3，输出是 ADR 文档或设计方案，不写代码。核心产出是 ADR（架构决策记录）。

## 流程

### Step 1 — 需求确认
问清楚：
- 要做什么决策或设计？
- 约束条件是什么？（团队技术栈、时间、成本、性能要求）
- 有哪些候选方案？
- 决策的优先级是什么？（可维护性 > 性能 > 开发速度？）

### Step 2 — 方案

输出一份 ADR，参照 `docs` skill 的 ADR 模板。至少列出 2 种候选方案，每个方案的优缺点要具体。

ADR 覆盖什么：
- 选择框架、库、主要依赖
- 设计数据模型或数据库 schema
- 选择认证策略
- 确定 API 架构（REST vs GraphQL vs tRPC）
- 选择构建工具、托管平台、基础设施
- 任何难以撤销的决策

### Step 3 — 门禁
question: "ADR 已写好，列出了 [N] 种方案和推荐选择。需要我展示完整内容供你审批吗？"

### 后续
- 你审阅 ADR
- 反馈修改意见
- 定稿后保存到 `docs/adr/` 目录
- 不需要编码、测试、部署

## 关键原则

- 至少 2 种候选方案，每种的优缺点要具体
- 决策有明确理由，不凭感觉
- 旧 ADR 不删除，新 ADR 可取代旧 ADR
- ADR 跟代码一起提交到版本控制

# 热修复

## 概述

热修复用于生产环境紧急情况，此时常规流程会造成不可接受的延迟。流程会被精简但绝不会被跳过。每一步都会执行 —— 只是更快。

## 流程适配

### 第 1 步 — 澄清
仅需快速确认：
- 哪里出了问题？
- 在哪里（哪个环境、哪些用户）？
- 严重程度（影响多少用户、营收影响）？
- 时间紧迫性（需要多快上线）？

### 第 2 步 — 规格与计划（精简版）
- 快速定位根因
- 设计最小修复（能解决紧急情况的最小改动）
- 写 3-5 行的计划
- **跳过多轮评审** —— 一次快速的自我检查即可

### 第 3 步 — 权限门禁
说明："生产环境问题：[哪里出了问题]。根因：[已定位]。修复方案：[最小改动]。预估风险：[低/中/高]。是否可以部署？"

### 第 4 步 — 开发
- 尽可能小的改动
- 本地测试修复
- 不要重构或改进周边代码
- 记录引入的任何技术债务

### 第 5 步 — 验收
- 部署到生产环境
- 验证修复在生产环境中解决了问题
- 部署后监控 15-30 分钟

### 第 6 步 — 事后复盘
紧急情况解决后：
- 创建跟进任务，进行正式的根因分析
- 安排"真正的"修复（如果热修复只是临时方案）
- 记录发生的事情

## 常见借口

| 借口 | 现实 |
|------|------|
| "这是生产环境，我就不检查了" | 恰恰是在生产环境才更需要检查。 |
| "我以后会好好修的" | 你不会的。现在就创建工单。 |
| "根因很明显" | 先验证。明显不等于正确。 |

## 验证清单

- [ ] 修复在生产环境中解决了报告的故障
- [ ] 未引入新问题（已监控）
- [ ] 已为正式的根因分析创建跟进工单
- [ ] 临时性规避方案已记录

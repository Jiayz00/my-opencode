
# 功能开发 — 前后端结合（集成角色）

## 概述

本参考资料用于「前后端结合」角色。职责：接收前端开发与后端开发提交的 PR，审查后通过受保护 PR 流程合并到 `develop`，进行接口适配，完成全栈验证，编写项目文档，并准备 `develop -> main` merge PR。最终 merge 仅由人工执行。

**思想（详见 `references/philosophy.md`）**：契约是唯一真相（卡片 1）、最小适配（卡片 4）、守卫 main（卡片 5）、能跑→对→快（卡片 12）。

## 角色边界

- 只处理他人已提交的 PR、接口适配与项目级文档，不从零实现前端或后端功能（除非适配必需的最小改动）
- 前端功能细节、后端业务逻辑分别由前端/后端开发人员负责，发现问题时退回对应开发人员
- 契约（`docs/api-contracts/`）是结合的依据：前端按契约 Mock，后端按契约实现，本角色负责消除两者差异

## 步骤调整

### 第 1 步 — 需求澄清
确认：
- 本次要处理的 PR 清单（`gh pr list --base develop` 列出 open PR，只提取 number/state/url）
- 前端 PR 与后端 PR 的配对关系（哪个前端功能需要哪个后端接口）
- 契约差异：前端使用的 API 契约 vs 后端实际实现的差异
- 适配点：字段映射、状态码、错误格式、CORS、鉴权方式

### 第 2 步 — 规格与计划
规格必须包含：
- PR 清单与合并顺序
- 接口适配点列表（Mock→真实接口替换、字段重命名、默认值、错误处理对齐、代理/CORS 配置）
- 契约文档更新计划（`docs/api-contracts/` 定稿）
- 项目文档清单（README、架构说明、启动指南、部署说明）
- 全栈验证计划（本地联调场景 + 测试容器部署场景）

### 第 3 步 — 权限门禁
本步骤只批准当前计划和当前阶段。每个 PR merge、环境部署、兼容性测试和创建 main PR 仍须在对应操作前分别请求许可；不得用一次确认覆盖整个发布链。

### 第 4 步 — 开发
1. **合并 PR**：按 `references/workflows/integrate-flow.md` 在隔离候选结果上先审查、测试和扫描，再通过受保护 PR merge 合入 `develop`；不得直接 push `develop`
2. **接口适配**（按 `references/api-contract.md` 核对清单执行）：
   - 前端 API 层从 Mock 切换到真实后端接口（关闭 Mock 开关）
   - 字段映射：对齐前端期望字段与后端返回字段（重命名、默认值、空值处理）
   - 错误处理：后端错误码/消息与前端展示对齐
   - 连接配置：开发代理、CORS、环境变量校验
   - 补漏：契约缺失字段、分页/排序参数、鉴权头传递
3. **全栈联调**：本地启动前端 + 后端，跑通核心用户流程
4. **编写项目文档**：README（项目简介、目录结构、启动方式）、架构说明、部署说明；整理 `docs/api-contracts/` 为最终契约
5. **工程化门禁**（vibe coding 平衡，思想见 `references/philosophy.md`）：适配改动过 lint/类型/测试；Mock 残留扫描（mock/fake 字样）；契约一致性核对；越界检查（是否夹带功能改动 → 退回开发人员）

### 第 5 步 — 验收
- 读取 `references/acceptance-fullstack.md`，部署隔离测试环境
- 验证端到端用户流程（UI → API → DB → 响应 → 展示）
- 确认前端 Mock 已关闭、真实接口连通
- 发现问题：小修返回第 4 步，方案问题返回第 2 步

### 第 6 步 — 兼容性测试
1. **门禁：** 向用户请求许可后读取 `references/compatibility-test.md`，在隔离测试环境中执行全栈回归
2. 发现问题：汇总返回第 2 步
3. 通过后：**提交 develop → main 的 merge PR**（`gh pr create --base main --head develop`，描述含适配与验证摘要）；**Do NOT merge** —— merge 由人工在 GitHub 手动点击执行，禁止直接 push main
4. 合并后验证 main 上 CI/测试通过，向用户报告结果

## 常见借口

| 借口 | 现实 |
|------|------|
| "前端后端我都改一下更快" | 越界。问题退回对应开发人员在自己的流程里修。 |
| "Mock 数据也能演示，先这样吧" | Mock 不替换等于没有结合。必须切到真实接口。 |
| "PR 合并进去就完事了" | 合并只是开始。适配、全栈验证、文档、合 main 才算完成。 |
| "直接 push 到 main 就行" | 禁止。合入 main 只提交 merge PR，人工手动 merge。 |
| "契约文档后面再补" | 契约不同步 = 新的差异源。先对齐文档再改代码。 |

## 验证清单

- [ ] 前端/后端 PR 已合并到 develop（每个都经用户确认、冲突处理、合并后重测、脱敏扫描）
- [ ] Mock 已替换为真实接口，无假数据残留
- [ ] 字段与错误处理对齐，无契约残留差异（`references/api-contract.md` 核对清单）
- [ ] 端到端流程正常（UI → API → DB）
- [ ] 项目文档（README、docs/）已更新，契约已定稿
- [ ] 全栈验收（第 5 步）与兼容性测试（第 6 步）通过
- [ ] develop → main 的 merge PR 已提交（base=main），未直接 push main

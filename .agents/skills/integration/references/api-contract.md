
# API 契约核对与适配

## 概述

本参考资料是结合角色的核心工作：**核对契约、消除差异**。前端按契约 Mock，后端按契约实现，本角色用系统化清单找出两者与 `docs/api-contracts/` 的差异并收敛。

**思想（详见 `references/philosophy.md`）**：契约是唯一真相（卡片 1）、消费者驱动的契约（卡片 2）、挖掘隐藏耦合（卡片 3）、兼容性优先（卡片 10）。

## 三类契约（CDC 模型）

| 类型 | 特征 | 在项目中的体现 |
|------|------|---------------|
| 提供者契约 | 闭、全、单一、权威 | 后端实际实现的全部端点与行为（记录型参考，非裁决依据） |
| 消费者契约 | 开、不完整、多、非权威 | 前端、移动端、内部服务、第三方客户端或 webhook 等已登记消费者实际依赖的子集 |
| 消费者驱动契约 | 闭、全、单一 | `docs/api-contracts/` 定稿（已登记消费者需求 ∪ 已发布提供者承诺），定稿后成为权威基准 |

**核对原则：契约义务来自所有已登记消费者和已发布提供者承诺。** 未被任何消费者依赖且从未承诺的内部字段不构成契约；修改任一消费者依赖或已发布承诺都必须评估兼容性。

## 核对维度清单（逐端点执行）

### 1. 端点与参数
- [ ] 路径与 HTTP 方法一致（大小写、复数、嵌套层级）
- [ ] Path 参数（`/users/:id`）名称与传递方式一致
- [ ] Query 参数：名称、可选性、默认值、枚举值一致
- [ ] Request Body：字段名称、类型、必填性、嵌套结构一致

### 2. 响应结构
- [ ] 顶层结构（`{ data: ... }` 包裹？直接对象？）一致
- [ ] 字段名称与类型一致（string/number/boolean/object/array）
- [ ] 可选字段与空值语义一致（`null` vs `undefined` vs 缺失 vs `""`）
- [ ] 嵌套层级与数组结构一致（`items[]` vs `data.items[]`）
- [ ] 枚举值集合一致（状态值：`active`/`pending`…）

### 3. 错误结构（必查）
- [ ] 错误状态码语义一致（400/401/403/404/409/422/500）
- [ ] 错误体结构一致（按后端统一错误结构规范：`{ error: { code, message, details, requestId } }` 包裹结构；字段语义：code 机器可读/ message 用户可读 / details 字段级 / requestId 追踪）
- [ ] 错误码枚举对齐（前端展示依赖的错误码后端真实返回）
- [ ] 字段校验错误格式一致（哪个字段错了、如何表示）
- [ ] **不泄露内部结构**：契约文档与错误响应示例不得含堆栈、SQL、内部路径、第三方凭据（定稿前按 git-workflow 脱敏表复查）

### 4. 分页（如适用）
- [ ] 请求参数一致（`page`/`pageSize` vs `cursor`/`limit`）
- [ ] 响应分页字段一致（`total`/`hasMore`/`nextCursor`）
- [ ] 页码越界、空列表行为一致

### 5. 鉴权与认证
- [ ] Token/Header 传递方式一致（`Authorization: Bearer`？自定义头？）
- [ ] 401 未登录与 403 无权限语义区分
- [ ] 登录态失效的处理（前端跳转逻辑 vs 后端响应）

### 6. 幂等与并发（写操作）
- [ ] 写端点幂等标注与契约文档一致（Idempotency-Key/唯一约束，幂等设计规范见 `docs/api-contracts/` 与后端设计文档）
- [ ] 重试语义一致（前端重试策略 vs 后端幂等保障）

## 差异处理流程

```
识别差异 → 分类 → 处理 → 更新契约 → 验证
```

**差异分类（决定谁改）：**

| 类别 | 判定 | 处理 |
|------|------|------|
| 前端错 | 后端与契约一致，前端 Mock 偏离 | 退回前端开发人员修正 Mock/调用 |
| 后端错 | 契约与前端一致，后端实现偏离 | 退回后端开发人员修正实现 |
| 契约错 | 前后端都对，契约文档过时/缺失 | 本角色更新契约文档（定稿） |
| 适配需求 | 合法差异（如 Mock 占位、临时兼容） | 本角色做最小适配（标注原因） |

**处理规则：**
- 功能逻辑差异 → 退回开发人员，不自己改
- 契约文档差异 → 本角色负责：按消费者清单与已发布承诺更新 `docs/api-contracts/`
- 适配代码必须标注存在原因（关联契约差异编号），能删则删

## Mock 替换检查清单

- [ ] 前端 Mock 开关已关闭，API 层指向真实后端地址
- [ ] 无硬编码假数据残留（在**生产代码**中搜索 mock/fake/stub 字样与假数据文件；**测试文件与 jest.mock/vi.mock 等测试 Mock 不属于残留**）
- [ ] 开发代理已配置（`/api` → 后端地址）
- [ ] CORS 白名单包含真实前端来源
- [ ] 环境变量校验：前端 API 地址、后端服务地址均已配置

## 兼容性检查（契约变更时）

- [ ] 只加不改不删：新增字段/端点可接受；删除/改名/改类型 = 破坏性变更
- [ ] 破坏性变更必须：版本化（`/api/v2`）或走契约评审（退回想改的一方走变更流程）
- [ ] 向后兼容：已发布的契约承诺不撤回
- [ ] 契约测试建议：对核心端点做 schema 校验（JSON Schema/Zod）或契约测试（Pact），让差异在 CI 中自动暴露

## 常见借口

| 借口 | 现实 |
|------|------|
| "后端返回的字段多点，前端忽略就行" | 忽略是隐藏耦合。契约文档必须记录实际使用子集 |
| "契约文档太麻烦，直接改代码最快" | 文档不同步 = 下一个差异源。契约先于代码 |
| "这个字段两边叫法不同，适配一下就行" | 适配要标注原因并记入契约差异清单，否则没人知道为什么 |
| "前端用到的字段后端都有，不用写契约" | 没有文档的契约 = 口头契约。下次改动就破 |

## 验证清单

- [ ] 核对维度清单已逐端点执行（参数/响应/错误/分页/鉴权/幂等）
- [ ] 差异已分类（前端错/后端错/契约错/适配需求）并处理
- [ ] `docs/api-contracts/` 已更新定稿（以消费者需求为准）
- [ ] Mock 已替换，无假数据残留（生产代码）
- [ ] 真实接口连通且与契约一致
- [ ] 契约测试/schema 校验已覆盖核心端点（如有能力）
- [ ] 契约文档与错误示例无内部结构泄露（堆栈/SQL/路径/凭据）
- [ ] 无未经标注的适配代码

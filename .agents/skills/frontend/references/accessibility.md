
# 前端可访问性（a11y）

## 概述

本参考资料提供前端可访问性规范与审查清单，浓缩自社区通行实践（Front-End Checklist a11y 规则、WAI-ARIA 实践）。适用场景：

- **开发时（第 4 步）**：按清单自检新增/改动组件
- **验收时（第 5 步）**：用自动化工具 + 手动检查验证
- **评审时（`references/review-frontend-architecture.md`）**：作为可访问性维度审查依据

**核心原则**：可访问性不是附加项，是功能的一部分。加载/空/错误状态、键盘交互、屏幕阅读器支持与视觉呈现同等重要。

## 语义结构

- 使用正确 HTML 元素表达语义（`button` 而非 `div` 绑点击；`nav`/`main`/`header`/`footer` landmarks；`ul` 列表）
- 页面有且仅有一个 `main`；标题层级不跳级（h1→h2→h3），不因视觉需要降级
- `html` 标签带正确 `lang` 属性；动态内容语言切换时更新
- 重复性导航/侧边栏提供 skip link（跳过导航直达主内容）

## 键盘可访问

- 所有交互元素可聚焦、可操作（Tab 可达、Enter/Space 触发、Esc 关闭）
- 焦点可见：`:focus-visible` 样式不被移除（禁止 `outline: none` 无替代）
- 焦点顺序符合视觉顺序；弹窗/菜单打开时焦点移入，关闭时焦点归还触发元素
- 弹窗、抽屉等覆盖层锁定 Tab 循环（focus trap）
- 页面内容更新（弹窗、路由切换、异步结果）时管理焦点而非放任跳回页面顶部

## ARIA

- 优先原生语义，ARIA 仅在无原生替代时使用（ARIA 是最后的工具）
- 动态区域（加载结果、错误提示、倒计时）用 `aria-live`/`role="status"` 播报，默认 `aria-live="polite"`，紧急用 `assertive`
- 弹窗用 `role="dialog"` + `aria-modal`；菜单/标签页用对应模式（tabs/tablist）；进度用 `aria-busy` 或 `progressbar`
- 图标按钮必须带可访问名称（`aria-label` 或文本）；装饰性图标 `aria-hidden="true"`
- 自定义组件实现键盘交互（箭头键导航等），不可只有点击

## 表单

- 每个输入有可见 `<label>`（`for`/`htmlFor` 关联，或 `aria-labelledby`）
- 必填标记（`required` + 可见 `*`）、错误信息用 `aria-describedby` 关联且错误后焦点移入
- 相关联字段用 `fieldset`/`legend` 分组（单选组、地址等）
- 表单提交失败不清空已填内容；错误提示说明如何修正，而非仅"提交失败"

## 色彩与对比度

- 正文/常规文本对比度 ≥ 4.5:1，大文本 ≥ 3:1（WCAG AA）
- 不依赖颜色单独传达信息（错误/成功同时用图标或文字标注）
- 链接与正文通过下划线/图标区分，而非仅颜色
- 支持深色模式时两套主题均需验证对比度

## 动效与运动

- 尊重 `prefers-reduced-motion: reduce`：动画、滚动效果、自动轮播降级或禁用
- 无每秒 3 次以上的闪烁（防光敏性癫痫）；自动轮播提供暂停按钮

## 图片与媒体

- 内容图片有描述性 `alt`；功能图标用按钮文本或 `aria-label`；装饰图 `alt=""`
- 视频提供字幕/转录；音频提供转录
- 表格用 `caption` + `th scope`；数据表结构正确

## 自动化工具

| 工具 | 用途 |
|------|------|
| axe-core（Playwright 集成） | 自动化扫描 WCAG 违规（运行时） |
| jest-axe | 组件测试中断言无 a11y 违规 |
| Lighthouse a11y 评分 | 整体可访问性检查（目标 ≥ 90） |
| Playwright 手动模式 | 键盘走查（纯 Tab/Shift+Tab 完成核心流程） |

## 验收清单（第 5 步使用）

- [ ] 只用键盘完成核心用户流程（Tab/Enter/Space/Esc，焦点可见）
- [ ] 屏幕阅读器（或 axe 扫描）无严重违规
- [ ] 所有状态（加载/空/错误/成功）有非视觉提示
- [ ] 对比度满足 WCAG AA
- [ ] `prefers-reduced-motion` 生效
- [ ] 弹窗焦点管理正确（打开移入、关闭归还、焦点锁定）
- [ ] 表单标签关联正确、错误提示可读
- [ ] 自动化扫描（axe/Lighthouse）无新增违规

## 常见借口

| 借口 | 现实 |
|------|------|
| "用户都用鼠标，键盘无所谓" | 键盘支持是无障碍的基线，很多用户（含专业用户）只用键盘 |
| "对比度差不多就行" | 视觉障碍用户会被差对比度卡住。4.5:1 是门槛不是目标 |
| "ARIA 加得越多越无障碍" | 错误的 ARIA 比没有更糟。优先原生语义 |
| "验收时再补 a11y" | 事后修补成本高。开发时就按清单写 |
